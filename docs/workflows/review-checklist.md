# Review Checklist — Molebot Mantle

> Проходится reviewer-агентом по каждому PR перед `approve`.
> Структура по мотивам ECC (quality + security + verification gate).
> Результат: `approve` ЛИБО список конкретных замечаний → `changes_requested`.

## 0. Pre-flight (без этого — REJECT сразу)
- [ ] PR существует на GitHub, ветка `feat/<ID>-*` создана из актуального `main`.
- [ ] PR ссылается на таск (`Closes <ID>`), таск в `status: in_review`.
- [ ] CI зелёный (или явно объяснено, почему нет).

## 1. Соответствие задаче
- [ ] Реализованы все acceptance criteria из `tasks/<ID>.md`.
- [ ] Нет scope creep — только то, что в таске. Лишнее → отдельный таск.
- [ ] Изменения ограничены файлами, заявленными в плане (или объяснено расширение).

## 2. Корректность кода
- [ ] **TypeScript:** `tsc --noEmit` без ошибок во всех изменяемых пакетах. 
      ⚠️ Viem v2: `writeContract` требует `chain`, `publicClient` ≠ `walletClient`.
- [ ] Компилируется (`hardhat compile`, `npm run build`) без ошибок.
- [ ] Тесты есть для критичной логики и проходят.
- [ ] Обработка ошибок и краевых случаев присутствует.
- [ ] Нет мёртвого кода, закомментированных блоков, отладочных `console.log`.

## 3. Безопасность (security gate)
- [ ] 🔴 **Нет хардкода секретов** (ключи, токены, seed, RPC с креденшелами). Всё через env/Infisical.
- [ ] Нет инъекций (shell / SQL / template).
- [ ] Input validation на внешних endpoint'ах; rate limit / body-size limit где нужно.
- [ ] Секреты не утекают в логи/ошибки.
- [ ] **Solidity:** reentrancy-guard где нужно, корректные `onlyOwner`/`onlyAgent`, нет overflow-проблем, правильные ERC-стандарты, нет лишних прав у агента.
- [ ] Никаких операций с реальными средствами/mainnet без человеческого approve.

## 4. Качество и поддерживаемость
- [ ] Зависимости запинены (pinning), нет случайных мажорных бампов.
- [ ] Код читаем; нетривиальные места прокомментированы.
- [ ] Нет дублирования с существующим кодом (reuse > rebuild).

## 5. Документация
- [ ] Если изменилась архитектура — обновлён `docs/architecture.md`.
- [ ] Если изменился процесс деплоя/env — обновлены соответствующие docs.

## Вердикт

- ✅ **Approve** — все блоки пройдены. Перевести таск в `status: approved`, уведомить человека (decision gate).
- 🔴 **Changes requested** — перечислить замечания списком (файл:строка + что не так + предложение). Перевести таск в `status: changes_requested`.

> Reviewer не чинит код сам. Нашёл проблему → конкретное замечание в PR → возврат coder'у.
> Исключение: security-hotfix может быть смержен с post-factum ревью в течение часа (по решению человека).
