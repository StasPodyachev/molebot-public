# FE-24 — Chat: batch approve 10 сообщений одним EIP-712

## Контекст
Сейчас каждое сообщение в чате требует отдельный MNT-перевод (0.001 MNT).
Пользователь хочет подписать один раз на 10 сообщений — backend списывает
по одному, пока лимит не исчерпан.

## Acceptance criteria
- [x] EIP-712 подпись включает поле `spendLimit: 10` вместо per-message tx
- [x] Backend принимает session: {tokenId, spendLimit, used, validUntil}
- [x] Frontend показывает счётчик: осталось N из 10 сообщений
- [x] После исчерпания — кнопка "Подписать новую сессию"
- [x] VITE_CHAT_SKIP_PAYMENT=true — безлимит (dev)
- [x] `npm run build` проходит

## Затронутые файлы
- `frontend/components/ChatPanel.tsx` — EIP-712 + счётчик
- `frontend/lib/contract.ts` — CHAT_FEE_ETHER, SPEND_LIMIT

## План
1. В EIP-712 ChatPayment: добавить поле `spendLimit` (uint256)
2. В ChatPanel: signChatPayment включает limit=10
3. Ответ от /api/chat: {ok, reply, remaining, spendLimit}
4. UI: progress bar "N/10 сообщений"
5. При remaining=0 — кнопка "Подписать ещё 10"

## Notes / лог
- Архитектура описана в T-LLM-01 (backend-счётчик микроплатежей)
- Backend должен быть развёрнут и принимать POST /api/chat + GET /api/chat/quota
- DeepSeek ключ нужен для реальных ответов крота
