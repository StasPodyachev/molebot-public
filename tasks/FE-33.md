# FE-33 — Chat: реальный DeepSeek + getMoleData fix

## Контекст
Чат отвечает шаблонными фразами, хотя DeepSeek API ключ уже есть
(`sk-67fa98...8b74`) и LLM Gateway работает в production mode.

## Root causes (из логов mantle-agent)

### 1. Неправильная модель
`llmClient.ts:41`: model hardcoded как `molebot-chat`.
DeepSeek отвечает: `supported models are deepseek-v4-pro or deepseek-v4-flash`.

Надо: `deepseek-v4-flash`.

### 2. getMoleData падает с out of bounds
`Position 191 is out of bounds (0 < position < 160)`.
Контракт возвращает данные длиной 160 bytes, но ABI парсинг пытается
читать позицию 191. Возможно, структура `getMoleData` изменилась после
деплоя — нужно сверить ABI с реальным контрактом.

## Acceptance criteria
- [ ] Чат отвечает через DeepSeek, а не шаблоном
- [ ] Ответы контекстные: учитывают tokenId, mood, стратегию

## План
1. `agent/src/services/llmClient.ts`: `model: 'molebot-chat'` → `model: 'deepseek-v4-flash'`
2. `agent/src/services/chatMoodService.ts`: проверить ABI `getMoleData` —
   выставить правильные позиции полей (serialNumber, personalityHash, mood, levelIndex, ...)
3. Пересобрать образ: `docker compose build mantle-agent && docker compose up -d`
4. Проверить: `curl POST /api/chat` → ответ от DeepSeek
