# FE-22 — ChatPanel: человеческие ошибки и debug-логирование /api/chat

## Контекст
После FE-17 (реальный MNT-перевод) /api/chat может возвращать ошибки (неверная сумма, не тот получатель, etc).
Фронт показывает сырой `errorCode: errorMessage` — неудобно для пользователя.
Также нет debug-логирования запросов/ответов.

## Acceptance criteria
- [x] `console.debug` лог запроса (payload) и ответа (status + body) для POST /api/chat
- [x] При `ok: false` ошибка показывается человеческим текстом, не raw errorCode
- [x] При network error (fetch fail) показывается 'Сервис чата временно недоступен'
- [x] Существующие тесты проходят

## Затронутые файлы
- `frontend/components/ChatPanel.tsx`

## План
1. Добавить `console.debug` перед fetch и после получения ответа
2. Сделать mapping errorCode → человеческий текст
3. В catch-блоке отличать network error от остальных
