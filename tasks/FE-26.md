# FE-26 — Chat: после подписи EIP-712 пустой ответ от /api/chat/session

## Контекст
FE-25 починил Privy popup (EIP-712 подпись показывается). Пользователь подписывает:
```
domain: MolebotChat / v1 / 5003
message: tokenId:1 / spendLimit:10 / timestamp: 1780589736
```

После подписи фронт отправляет `POST /api/chat/session` с {tokenId, signature, spendLimit, timestamp}.
Ответ: пустое тело → JSON.parse падает → "Сервис чата временно недоступен (пустой ответ)".

## Root causes (coder-диагностика)

1. **deploy-mantle.sh**: `[ -f agent/Dockerfile ]` — Dockerfile лежит в корне репо, не в `agent/`.
   Docker-образ mantle-agent **никогда не пересобирался** при деплое.

2. **docker-compose.mantle.yml**: `image: ghcr.io/...` без `build:` секции — docker compose всегда
   тянет stale образ с GHCR. Даже если бы скрипт собрал локально, compose бы не использовал его.

3. **chatRouter.ts**: Нет логгирования входящих запросов — невозможно понять, доходит ли тело
   до агента или теряется раньше.

4. **Caddyfile.mantle**: Отсутствовали явные `header_up X-Forwarded-*` для корректной
   передачи метаданных запроса, нет `flush_interval -1` (буферизация может блокировать ответ).

## ❌ Не сработало (почему)

### 1. CF Pages _redirects status 200 для POST
`/api/* http://178.105.123.110/api/:splat 200`
**Причина:** CF Pages _redirects с status 200 проксирует только GET.
POST возвращает 405.
**Правильное решение:** фронт вызывает VPS напрямую через CORS + CSP.

### 2. Cloudflare Worker + route
Создан Worker `molebot-api-proxy`, но route `mantle.molebot.org/api/*`
не удалось добавить — у токена не было прав Workers Routes для зоны.
**Правильное решение:** DNS A-запись vps.molebot.org через Cloudflare Proxy.

### 3. Pages Functions (`frontend/functions/api/[[path]].ts`)
Не подхватились `cloudflare/pages-action` — action ожидает functions/
в корне проекта, а не в output-директории.
**Правильное решение:** не Pages Functions, а прямой HTTPS через DNS.
